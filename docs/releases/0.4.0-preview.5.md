# 0.4.0-preview.5 — Visible offline MIDI assignments

Application MIDI bindings now remain visible on their saved VAIO/AUX/VAIO 3 page when their app disappears or moves to another input. A red status explains whether the app is offline, appears on another input, or its saved input is unavailable. The source column keeps the MIDI channel and CC/note visible. Paused apps with a valid session remain controllable.

**Delete row** frees that MIDI control and immediately saves the application setup. Deleted bindings are omitted from the file, so they cannot return after relaunch. Other controls keep running. If saving fails, the row remains intact and an error explains that deletion did not complete.

**Show removed** can redisplay an app during the current run, but never restores deleted MIDI. On relaunch, a connected app may appear as an unchecked, unlearned discovery row. Older hidden learned bindings become visible and disabled for cleanup.

Strip/bus pickup and the combined Windows Audio / VoiceMeeter reset are retained. This remains an unsigned local preview.

## Test with your MIDI device

1. Save an application assignment, then close the app or move it to another input and refresh/reset the session list.
2. Check its original page still shows the assignment and a red status. The binding must not follow the app to another input.
3. Delete that row. Learn its former MIDI control on another app.
4. Relaunch Elka and confirm the deleted binding remains absent. Recheck existing strip/bus pickup.

Debug and Release x64 each pass 43,153 regression checks. Silent test-owned audio-session integration passes in both configurations, including immediate deletion, a locked-file save failure, continued operation of another control, and reopening without deleted MIDI reservations. UI inspection confirms the red offline status and deletion of a test-only offline row.

Automated checks also cover moved-input identity and legacy hidden mappings. Live MIDI acceptance remains required.
